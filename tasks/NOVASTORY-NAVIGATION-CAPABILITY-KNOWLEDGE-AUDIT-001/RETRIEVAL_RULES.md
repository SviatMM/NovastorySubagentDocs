# NovaStory Retrieval Rules

1. Classify one primary direction.
2. Open `NOVASTORY_MAIN_MAP` → one direction route → exact canonical section.
3. For “works/change/run” claims add current-state + active UI wiring + host code/test/evidence as needed.
4. Expand another direction only when a named dependency becomes material.
5. Classify actor: human_ui / chat_model / project_agent / system_host / future automation/runner/connector.
6. Never substitute human UI authority for Chat/Agent authority.

## Source priority
Implementation: active code/tests > newest scoped current-state/evidence > frontend matrix > operation/data catalogs > older product docs. Product intent: current Owner instruction > accepted decision/canonical product > Owner Logic row authority > proposals/open questions. Delivery: STATUS plus its Boundary.

A YAML `status: current` is not enough when newer reconciliation supersedes an internal paragraph.

## Proof before “works”
Ask: active path? typed host operation for durable/external change? enabled rather than boundary? principal authorized? current evidence? Button/command/wrapper alone is insufficient.

## Synonyms
Chat/conversation → durable `Conversation`; Saved Agent → usually `AgentTemplate`; Project agent → `ProjectAgent`; repo/folder source → usually `ProjectSource`; Resource ≠ every source; Power = reasoning effort; Fast = separate service tier; delete Chat = current recoverable Trash; second computer/Home Mac = future runner; Smart Subagent = U-19/post-commit intent; result = distinguish Chat output from future Agent ResultReference.

## Deduplication
Indexes store pointers/status only. Preserve existing OL/CFG/capability/operation identifiers. Do not create parallel canonical definitions. Put conflicts in the contradictions file.

## Topic change / context loss
Stop old traversal, keep only true cross-cutting dependencies, return to main map and choose new route. Recover minimal state: source commit, user goal, primary route, exact entity/capability, last authoritative section, actor, implementation status, blocking U/CFG IDs, unverified assumptions.

## Drift
Before high-confidence current-state execution/publishing, verify source main still equals the pin. If it moved, revalidate only affected routes.

## Completion language
Allowed: “UI can”, “host path is wired”, “Chat can explain but not execute”, “ProjectAgent identity exists; Mission is not built”. Forbidden without proof: “I changed it”, “Agent ran it”, “Full access can write”, “backup restores everything”, “cloud automatically fails over”.
