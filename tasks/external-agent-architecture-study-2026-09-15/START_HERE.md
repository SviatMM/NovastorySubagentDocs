## Що це

Це незалежне зовнішнє дослідження майбутньої агентської системи з трьома ролями: Smart Subagent, NovaStory Agent і NovaStory Chat. Дослідження спирається на офіційну документацію GitHub та OpenAI, відкриті агентські системи й наукові роботи.

**Сувора межа дослідження:** репозиторій NovaStory не відкривався, не шукався і не використовувався. Цей пакет не робить тверджень про фактичну реалізацію NovaStory.

## Обмеження вхідних даних

Файл або ZIP `novastory-agent-files-audit` у цьому запуску не був доступний як прикріплений файл. Тому цей результат використовує текст поточного завдання як авторитетний опис задуму й проблем, але не робить жодних висновків, які вимагали б фактичного вмісту відсутнього пакета.

## Головна рекомендована схема

На першій версії варто тримати систему простою:

1. **GitHub handoff:** окрема гілка й папка конкретного завдання → push → підписаний webhook → основна система фіксує точний commit SHA → перевіряє маніфест, межі й результат → приймає або відхиляє саме цей SHA. Періодична перевірка є запасним каналом, але проходить той самий валідатор.
2. **Інструкції:** завжди завантажуються два невеликі versioned-файли: стабільний базовий файл ролі, потім інструкція власника. Дозволи й security gates не зберігаються як звичайні текстові побажання.
3. **Критичний Agent:** починає з task contract та умов готовності; додаткових виконавців запускає лише коли незалежність підзадач або незалежна перевірка реально додає користь; завершення оголошує лише після evidence-based verification.
4. **Natural Chat:** головна суть першою, далі причина → наслідок → приклад; точні терміни зберігаються, але пояснюються людською мовою; згода з користувачем не є default-поведінкою.
5. **Вибіркові знання:** короткий root index → тематичний index → capability → конкретний документ → конкретна секція. На v1 достатньо індексів, metadata та lexical/exact пошуку; semantic/hybrid/reranking додаються лише після виміряних промахів.

## Як читати статуси тверджень

### Підтверджений факт
Факт, що прямо підтримується зовнішнім першоджерелом, наприклад документацією GitHub або OpenAI.

### Приклад іншої системи
Реальна поведінка або архітектура зовнішньої системи. Це приклад, а не доказ того, що NovaStory повинна робити так само.

### Рекомендація для задуму
Висновок цього дослідження. Це не реалізована функція й не погоджене рішення власника.

### Припущення
Робоче припущення, потрібне для формування рекомендації, коли фактичний продукт не досліджувався.

### Ризик
Спосіб, яким схема може дати неправильний, небезпечний або дорогий результат.

### Відкрите рішення
Питання, де технічне дослідження може показати наслідки, але не повинно підміняти рішення власника.

## Що цей пакет не стверджує

- що будь-який описаний механізм уже існує в NovaStory;
- що NovaStory Agent і NovaStory Chat уже мають конкретну runtime-реалізацію;
- що GitHub є єдиним допустимим transport-механізмом у майбутньому;
- що кілька агентів автоматично кращі за одного;
- що складний semantic/graph retrieval потрібен з першого дня.
